# CD-MPM rebuttal reproducibility package

The self-contained reproducibility package is located in `reproducibility_rebuttal_20261007/`. It contains the aligned U.S. input tables, executable scripts, fold assignments, and reported result artifacts used for the reviewer-requested experiments. All default paths are relative to the package directory, and rerunning an experiment writes new artifacts under its ignored `outputs/` directory.

The package does **not** contain trained models or raw source archives. The committed input CSV files are processed, point-aligned model inputs for the western-U.S. study area; immutable copies of the predictions, metrics, selections, diagnostics, and manifests cited in the rebuttal are included under `results/reported/`.

## Scope and benchmark

- Main benchmark: 1,738 records, 158 positives and 1,580 hard negatives (1:10).
- Geographic scope: 11 western U.S. states.
- Primary validation: five state-grouped folds.
- Additional validation: 2-degree and 3-degree spatial blocks, boundary buffers, negative-source and class-ratio sensitivity.
- Leakage control: imputation, feature selection/graph construction, scaling, Ridge residualization, and classifier fitting are performed inside each training fold before held-out evaluation.
- Fixed downstream learner for the rebuttal reruns: XGBoost parameters are defined in `scripts/stage_16_rebuttal_experiments/xgb_model.py`.

## Environment

Recommended Python versions are 3.11 or 3.12.

Using `venv`:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Using Conda:

```bash
conda env create -f environment.yml
conda activate cd-mpm-rebuttal
```

PyTorch is only required for the IDANN-inspired comparison (`16_lin2025_idann_tabular.py`).

## Validate the package first

Run this command from this directory:

```bash
python scripts/00_validate_package.py
```

It checks required files, benchmark row/label counts, paleoclimate completeness, enhanced-ASTER feature count, absolute paths in Python files, unexpected files under `outputs/`, maximum file size, and the SHA-256 manifest.

## Reported result files

`results/reported/` contains the result artifacts promised in the rebuttal:

- original M1-M4 fold metrics, predictions, summaries, and M4 fold-local selections;
- fold-local and spatial graph targets, graph manifests, and per-fold graph/selection files;
- fixed-XGBoost OOF predictions, fold metrics, paired contrasts, diagnostics, random controls, and run manifests;
- paleoclimate, IDANN-inspired, basic ASTER, and enhanced-A132 ASTER result records.

See `results/README.md` and `RESULTS_MANIFEST.csv`. Absolute local paths in copied run manifests were replaced with the symbolic prefix `PACKAGE_ROOT`; metric and prediction values were not changed.

## Paleoclimate input note

`paleoclimate_aligned_1738.csv` contains all 1,738 benchmark identifiers. NASPA precipitation is available for all records; WNATA temperature is unavailable for nine negative records. The model sensitivity script uses the 1,729 complete records while retaining all 158 positives. WNATA is a June-August maximum-temperature anomaly and NASPA is December-April precipitation; they are not seasonally identical to the modern annual variables.

## Reproducibility boundaries

- Raw USGS, ASTER, TerraClimate, land-cover, WNATA, and NASPA archives are not redistributed here. The package contains only aligned derivative CSVs. See `DATA_SOURCES.md` for provenance and reconstruction boundaries.
- The Lin and Zuo (2025) script is explicitly an IDANN-inspired tabular implementation-level reference, not an exact reproduction of unavailable author code. DOI: `10.1007/s11004-024-10164-3`.
- The CausalAI comparison in the rebuttal refers to the M3 partial-feature residualization branch, not to a separate external CausalAI implementation. Its metrics, predictions, and scripts are included with the M1-M4 workflow.
- No software license is introduced by this subdirectory. Repository owners should add an explicit project license before describing the code as open source.

## Statistical reporting

Do not mix mean-fold and pooled-OOF estimands. Experiment reports label them separately. Top-K metrics measure prioritization within the constructed candidate pool; they do not estimate drilling cost savings or natural deposit prevalence.
